# Verification of media, sync, utility, and chat stacks

Tests ran on 2026-09-09 with rootless Docker on the test host. Each flavor used its own disposable directory outside this repository, disk-backed for Open WebUI, with its own Compose project, localhost HTTP port, data, and generated secrets. The DHI directories for qBittorrent, Navidrome, Syncthing, SerpBear, FreshRSS, Jellyfin, Open WebUI, and the WireGuard/AdGuard stack retain their pinned upstream images. They contain no `dhi.io` images and must not be described as hardened builds.

For each stack, the checks are Compose rendering, `prepare` exit status, `up -d --wait`, all service health or one-shot exit status, HTTP response, restart with the same data followed by another `up -d --wait`, and inspection of startup and restart logs. A passing restart confirms the service can reopen its data; it does not prove backup restoration or data migration from another release.

## Caveats and remaining deployment checks

- Open WebUI downloads its embedding model on first startup, about 890 MB in the test data directory. The public Hugging Face download emits a warning about unauthenticated rate limits, and the model loader reports an unused `embeddings.position_ids` key. Local administrator and chat persistence work. OpenAI and Ollama integrations are disabled in the supplied stack; no language-model response or remote provider credential was tested.

- Those eight DHI directories are upstream fallback stacks, including their BusyBox setup helper and the WireGuard stack's Python initializer. This split does not turn those images into Docker Hardened Images.
- Navidrome logs a warning that playlist import waits until the first administrator exists. The empty music directory was scanned successfully. The [additional functional checks](functional-checks.md) subsequently verified administrator onboarding, a generated WAV library scan, and byte-for-byte authenticated streaming after restart in both flavors. Browser audio-device playback, transcoding, and playlist import remain untested.
- Syncthing logs an `INF` message that the QUIC receive buffer could only grow to 416 KiB instead of 7168 KiB. The service stays healthy. No host sysctl was changed. The [additional functional checks](functional-checks.md) subsequently verified local peer pairing, transfers in both directions, and persistence after restart. External discovery, relays, and Internet peer reachability remain untested.
- SerpBear emits Node's `DEP0040` deprecation warning for `punycode`. Its API and SQLite database work. Keyword scraping remains idle until a real scraper and credentials are configured; no external scraper was tested.
- FreshRSS completes local setup with a generated administrator and SQLite database. No external feed fetch, SMTP delivery, or reverse proxy was tested. The example intentionally keeps the interactive setup workflow.
- Jellyfin emits `WRN` messages during initial Entity Framework migrations, about unencrypted data-protection key storage, a missing `/wwwroot`, initial user creation, and empty library directories. The web UI and authenticated library API work. Playback, hardware acceleration, and media metadata providers were not tested.
- qBittorrent starts with a generated password and keeps its configuration after restart. The [additional functional checks](functional-checks.md) subsequently verified administrator login and authenticated configuration persistence in both flavors. Torrent transfer and incoming peer reachability remain untested.

- WireGuard and AdGuard work with the test host's rootless Docker and existing kernel support. The healthcheck verifies the `wg0` interface and web UI. Real A/AAAA DNS queries succeeded through AdGuard before and after restart. No external VPN client or peer handshake was tested, and `vpn.example.com` was only a placeholder endpoint.
- AdGuard's initializer originally raced the HTTP listener during `docker compose restart`. Both copies now retry connection refusal for up to 15 seconds. Fresh initialization and restart then completed without initializer errors.
- AdGuard logs a warning that private reverse DNS is disabled without an upstream. wg-easy warns that IPv6 is disabled, as configured. Quad9 HTTPS `unexpected EOF` errors occurred with the original implicit upstream while DNS resolution still succeeded. The examples now set `ADGUARD_UPSTREAM_DNS=https://cloudflare-dns.com/dns-query` on first setup. Existing installations keep their saved DNS settings; change the upstream in the AdGuard UI. Final fresh tests confirmed that exact Cloudflare upstream in saved configuration and via the authenticated API, successful A/AAAA resolution before and after ordered stop/up, and no error-level logs in either copy. AdGuard documents this [DNS-over-HTTPS upstream format](https://github.com/AdguardTeam/AdGuardHome/wiki/Configuration).
- AdGuard also logged an error when shutting down before any DNS queries had populated the query log. The initializer now sends a bounded real DNS query before WireGuard starts. Final fresh tests stopped each stack before sending any manual DNS traffic, then restarted it, verified A/AAAA resolution and HTTP 200, and stopped it again. Both complete lifecycle logs contain no error-level entries.

No `ERROR`, `ERR`, fatal exception, or failed container health result was observed in the seven pairs other than WireGuard/AdGuard. The final VPN test also has no error-level logs with the configured Cloudflare upstream and real DNS traffic. The warnings above remain visible; these results do not claim silent logs or full external integration coverage.

## Zulip dependency fixes

Zulip was transferred into this batch after the first eight applications. Its DHI recipe uses DHI PostgreSQL, Redis, RabbitMQ, Memcached, and BusyBox; the application and one-shot dependencies initializer reuse the pinned upstream Zulip image.

Fresh initialization originally logged a PostgreSQL error for missing `en_us.dict` and fell back to lower-quality search. The initializer now downloads [Debian hunspell-en-us 1:2020.12.07-4](https://deb.debian.org/debian/pool/main/s/scowl/hunspell-en-us_2020.12.07-4_all.deb), verifies SHA256 `962d774fd74f94ea8e781291319706fc5172d7d02c806e4c3a0c6af3ec9ccdc7`, and combines its dictionary and affix files with the pinned app image's Zulip stopwords. It preserves both source licenses in `dictionaries/`. PostgreSQL waits for initialization and mounts only those dictionary files read-only. Partial files use atomic replacement, and completed assets are reused.

The app container needs the `KILL` capability so the root supervisor can signal workers running as the Zulip user. Without it, normal stop operations logged `PermissionError` and forced shutdown.

The bundled Pika 1.4.0 also raised `RuntimeError: dictionary changed size during iteration` when closing active consumers. The initializer now fetches the [Pika 1.4.4 wheel](https://pypi.org/project/pika/1.4.4/), verifies SHA256 `48de960c97a93b55db06b8be4c53eb977c9c8a2754c57cdae9097abcbd70ce04`, and stores the unchanged wheel in `python-overrides/`. Its license and metadata remain inside the wheel. The app selects it from a read-only mount through its custom settings hook because `manage.py` resets `PYTHONPATH`. A focused test reproduces the exception with 1.4.0 and closes the same active-consumer scenario successfully with 1.4.4. The fix landed in Pika 1.4.1; remove this override when the pinned Zulip image bundles Pika 1.4.1 or later and passes the same shutdown tests.

The threaded queue configuration also produced first-start Python import deadlocks in markdown modules. Both copies now use Zulip's supported `queue_workers_multiprocess=True` setting, with a 3 GB app memory cap for the separate worker processes. The healthcheck also checks each configured RabbitMQ worker and the Tornado queue for an active consumer. Supervisor's `RUNNING` state alone was too early: stopping immediately could interrupt a worker before it entered its consume loop. Both final cold starts passed. Final tests confirmed all five long-running services healthy and both initializer jobs exiting 0, loaded Pika 1.4.4 through `manage.py`, logged in as the generated administrator, created a channel and message, stopped and started the stack with saved data, retrieved that message, and found its word `dancing` with the search query `dance`. Docker logs and on-disk application logs contained no error-level entries after the final shutdown in either flavor.

SMTP and mobile push were disabled, as the examples specify. No email delivery, push service, TLS terminator, or external authentication provider was tested.

## Stoat verification

The DHI flavor uses DHI MongoDB, the MongoDB compatibility image for its initializer, Redis, RabbitMQ, Caddy, Python, and BusyBox. Stoat application services, its web client, LiveKit, and Garage retain upstream images.

Both flavors include service probes for HTTP endpoints, WebSocket availability, and the worker connections to MongoDB or RabbitMQ. The crond probe reads `/proc/net/tcp`, where ports are hexadecimal; it originally looked for `6981` instead of `6989`, which is 27017. The corrected probe detects crond's established database connections. MongoDB now checks a live local TCP connection through the pinned BusyBox assets; a stale socket file no longer produces a healthy result. The MongoDB initializer waits for a writable primary for both fresh and existing administrator accounts. A controlled test of the extracted scripts delays election and checks timeout behavior. Both flavors passed full lifecycle reruns after these review fixes. The web client now executes its existing injector and static server directly, avoiding npm error messages when Docker sends SIGTERM during an ordered shutdown.

Both final runs created an account, logged in, completed onboarding, created a server and channel, sent a message with an uploaded attachment, and retrieved the attachment bytes. All 15 long-running services became healthy and both initializer jobs exited 0 in each flavor. After ordered stop/up, the same account logged in and the saved message and exact attachment bytes were retrieved. HTTP endpoints returned 200, the event connection upgraded to WebSocket, and RabbitMQ reported the expected notification consumers. The final full lifecycle logs, including shutdown, contain no error-level entries. The scan includes lowercase npm error labels, which exposed the web shutdown issue in an earlier run. Evidence and summaries are kept outside this repository. Each `verified-summary.json` records the tested Compose SHA256; both match the current recipes. A disk-full attempt left an empty RabbitMQ cookie and was discarded after its logs were saved. Fresh reruns after reclaiming test disk space passed.

SMTP verification, external GIF providers, mobile push, a remote TLS proxy, and live voice/video calls were not tested. Registration works with the SMTP-disabled configuration; the [upstream defaults](https://github.com/stoatchat/stoatchat/blob/v0.12.1/crates/core/config/Revolt.toml) disable email verification when no SMTP host is configured. Stoat is a fork of Revolt, which is why the file is named `Revolt.toml`. MongoDB emits startup warning and informational messages while the fresh replica set elects its primary and creates its collections; there are no MongoDB error or fatal severity entries. Garage initializes its single-node layout before Autumn and crond start; its missing-layout first-start message is informational, and the complete tested lifecycle contains no Garage error-level entries.

## Cleanup

All test projects in this batch were stopped and removed after recording results. Generated credentials and bind data from the Zulip, WireGuard/AdGuard, and Stoat final runs were removed. Their configuration copies and test evidence remain outside the repository. The 4.18 GB Zulip app image and unused Stoat images were removed after both flavors passed. No shared Docker image prune was run.
